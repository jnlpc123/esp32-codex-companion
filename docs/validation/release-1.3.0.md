# 1.3.0 恢复出厂验证

2026-10-29，Windows / ESP32-C3，基于1.2.1。

新增恢复出厂共享协议、USB本地后台与Wi-Fi后台入口，以及正常运行后长按BOOT10秒、松开执行。后台须输入RESET并匹配设备身份。升级不擦数据。

自动覆盖：C恢复引擎持久标记与启动无请求不擦除；格式化/各命名空间提交失败及下次启动重试；保留校准空间；忙碌拒绝；按键启动低电平、短按、抖动、长按及释放；JS取消、错误输入、设备绑定及ACK缺失；实际Python管理服务能力门控、身份/Origin/令牌保护和串口队列单次转发。

实机：COM9 / 58e6c5994c6c，4MB ESP32-C3。先取得并在停止运行的bootloader中核验整片Flash备份。只更新应用后，原设置保持。通过真实Python HTTP后台→实际管理队列→USB串口执行恢复：错误确认/设备ID及导入忙碌被拒绝；恢复重启后50个文件清空、默认设置和AP模式恢复，中屏状态为原AP提示，SPIFFS总量/空闲均为2,583,041B，空文件系统空闲RAM67,120B。

实体按钮：首次操作未观察到重启；重复使用临时GPIO串口采样镜像，测得BOOT低电平持续超过14秒，松开后重启，默认设置、空文件系统和AP提示验证通过。生产判定函数与采样像一致，正式镜像移除全部临时采样。未进行物理断电破坏试验。

独立审阅发现配网与复位准入竞争，已改为共用存储互斥锁并对两种准入顺序回归；10秒精确边界已回归，NVS故障夹具按IDF即时写入语义覆盖失败set、部分erase及失败key清理，而非假定事务回滚。106项Python及17组Node/C测试通过。新增逻辑复用USB任务，无新增常驻任务或全帧缓冲。

正式应用1,136,800B（相对1.2.1增加2,912B），原应用分区仍余13%。已刷回不含临时GPIO采样的正式镜像并核对烧录哈希；仅恢复已核验备份的NVS和SPIFFS，保留新应用。原50个文件逐个SHA-256一致、原配置及忽略配网选项一致；Wi-Fi重新取得10.10.10.37。三屏帧率23.58/16.53/23.58FPS，按原素材时序；15次USB响应最大16ms。发行包从干净提交生成，manifest记录源码提交和测试结果；发布前对Windows和源码ZIP分别解压完整回归并核对附件SHA-256。私人Flash备份、配置、采样镜像及脚本不进入源码或发行包。

限制：断电恢复通过故障注入C测试验证，不进行带电拔插破坏Flash的试验；Flash/NVS硬件损坏不保证自动恢复。电脑端Codex账号、Hook信任及正在运行任务不属于设备恢复范围。
