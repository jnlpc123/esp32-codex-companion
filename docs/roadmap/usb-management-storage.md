# USB 后台与存储治理开发及主线合并计划

> 执行方式：superpowers:executing-plans。2026-10-27 已实施 1.1.0-rc.1 并烧录 COM10；本文件同时记录未完成的验收项，不能视为正式版全部通过。

**Goal:** 在弱 Wi-Fi 或无路由器环境下，通过现有 USB 数据线完整管理设备，并根据真实文件清单修复空间占用问题。

**Architecture:** 继续使用 ESP32-C3 原生 USB Serial/JTAG；现有 Python 桥接是串口的唯一所有者。浏览器访问电脑本地后台，后台通过受控队列复用桥接的 USB 通道；固件的 USB 和 HTTP 共用存储与导入业务实现。保留现有 Wi-Fi 管理入口及状态同步备用。

**Tech Stack:** ESP-IDF 6.1 / C、Windows Python 3（已验证 3.12）、原生 HTML/JS、现有 pyserial；优先使用 Python 标准库 HTTP 服务，不引入额外前端框架。

**Spec:** 本文“目标、约束及验收”作为本次方案草案；USB 后台是建议实施方向，蓝牙和录音恢复属于后续独立项目。用户要求保留未来录音能力，但尚未要求本次恢复录音。

## 2. 目标、约束及验收

### 必须交付

1. USB 下读取身份、固件版本、容量、文件分类及各素材占用。
2. USB 下调整现有设置、导入 GIF/PNG/JPG、查看预览和执行安全清理。
3. USB 上传不阻塞人工授权黄灯、完成提醒或任务心跳；保持串口单一所有权。
4. 普通升级、导入及诊断完整保留用户素材；只有用户明确确认下述“清除内存 / 全部清除”操作时，按其范围删除素材。NVS 中的其他设置、Wi-Fi 配置、状态计数、原有对比色弧形圆点、灰度暂停和空闲动画行为保留。
5. 先取证，再按原因释放空间；所有已完成但未选中的素材都视为用户资料，不能自动当作垃圾删除。
6. Wi-Fi 旧后台和旧桥接继续兼容；旧固件不支持的 USB 功能应明确提示需要升级。

### 本次不做

- 不做蓝牙后台，不恢复录音，不更换文件系统，不扩大或搬移分区，不调整灯光逻辑。
- 不保证所有动画三屏均达 30 FPS；使用相同素材与相同工作状态比较升级前后性能。
- 不自动清空素材、不恢复出厂、不添加开机计划任务，不改 Hook 信任记录。

### Review Focus

- 上传中拔线、断电、响应丢失：原素材仍可播放，新素材不误激活，重试不会重复追加。
- USB 插入另一块板子：未完成上传和写请求不得自动转投新设备。
- 后台管理流量不断但 Codex 已退出：管理请求不得伪装任务心跳维持绿灯。
- 空间接近耗尽、文件损坏或枚举失败：不虚报容量和可释放量，不格式化或删除未知文件。
- 恶意网页请求本地服务、并发上传和超大包：不能任意访问电脑文件或设备文件，也不能长期堵塞状态同步。

### Task 2 / PR 2：根据清单修复实际占用问题

**Files**
- 按证据修改 `main/file_server/import_transaction.c/.h`、`main/core/app_tasks.c`、`main/storage/fast_read.c`、`web/companion.js`。
- 新建 `tests/companion/test_storage_cleanup.cjs` 及主机 C 文件系统 fixture；扩展 `test_upload_failure.cjs`，加入回归入口。

**Decision gate**
- 若主要是有效动画：这不是容量故障。保留素材，显示各目录占用和导入预算，必要时建议缩短动画；不得把删掉用户文件称为修复。
- 若主要是无引用的生成缓存：复用动画任务的安全清理点，清理并核对释放量。
- 若主要是失败导入：修复导入标记、失败回滚或启动恢复的确切缺口；仍保留当前已选素材。
- 若主要是旧网页文件：先出明确白名单、确认是固件已内嵌的旧版本文件并备份；只能在用户明确选择迁移清理时删除。不能只根据 `.jpg/.js` 扩展名批量删除。
- 若是 SPIFFS GC/元数据异常：以快照复现读路径及 GC 问题；不默认格式化，也不先修改分区。

#### 用户已确定的双按钮规则（2026-10-27）

| 按钮 | 删除范围 | 必须保留 |
|---|---|---|
| **清除内存** | 除当前三屏正在展示的素材以外，全部已上传素材；同时清理不再使用的生成播放缓存 | 三屏当前使用的完整素材序列、预览和时序文件；正在播放所需缓存；所有非素材配置 |
| **全部清除** | 所有已上传素材，包含当前三屏正在展示的素材及其生成播放缓存 | Wi-Fi、亮度、颜色、音量、范围等非素材配置；系统及未知文件 |

“清除内存”实际清理的是 Flash 中的素材存储空间，不是运行 RAM。静默灰度暂停或空闲动画的已选素材也视为当前素材；保留整个序列，不能只保留正在显示的一帧。多个屏幕共用同一目录时，任意一屏仍在使用便保护整组。

**交互及接口约定**
- 两个按钮都先显示明确的删除确认；“全部清除”强调“包括正在展示的素材，无法撤销”。取消确认不发出写请求。
- 保留旧版 `prune_cache` 的“只清未用缓存”语义，避免旧网页或自动上传预检查误删完整素材。新增明确操作 `clear_media`，范围 `unused` / `all`；协议要求与范围匹配的确认字段，缺失或不匹配拒绝。
- 未用清理保持三屏选择不变；全部清除须先可靠保存空素材选择、停止并释放三屏播放句柄和缓存，再删除文件。后续重启不应重载已删除目录；信号灯及任务状态仍可正常显示。
- 文件删除由存储/动画所有者串行执行；上传、激活、设置切换与清理互斥。上传事务未结束时拒绝清理并提示稍后重试，不边上传边删除。
- 按业务确认的已上传素材文件及关联元数据删除，不按整个 `/data` 或所有 `.jpg/.js` 扩展名盲删；根目录 `config.json`、Wi-Fi/NVS、系统文件及无法判定来源的文件保留。
- 提示实际删除数量及清理前后剩余字节；逻辑文件字节与 SPIFFS 分配回收量分开报告。出现删除失败、枚举失败或部分成功时显示未完成，不宣称全部清空。
- 重复点击、USB 重连或响应丢失不得自动扩大删除范围；重新查询当前设备和清理结果，不能把请求转投另一块板子。

### Task 3 / PR 3：固件支持 USB 文件传输

**Files**
- 新建 `main/storage/media_transfer.c/.h`：文件状态机、块校验及有界读写。
- 重构 `main/file_server/import_transaction.c/.h`：抽出与 HTTP 无关的导入服务，原 handler 保持兼容。

**Interfaces**
- USB 命令：`import_begin/import_commit/import_abort`（目录事务）；`file_begin/file_chunk/file_end/file_status`（单文件）；`file_read`（预览分块读取）。
- 请求携带目录事务 token、文件 token、offset；单块原始数据最多 768 字节，Base64 后 1024 字节，整条请求和响应必须小于各自 2048 字节缓冲。
- `file_chunk` 校验 CRC32；仅接受连续 offset。重复提交相同块返回原进度，重复 offset 但数据不同必须拒绝。`file_end` 校验声明长度和整文件 CRC32。
- 初版单文件上限拟定 256 KiB，并在转换端核对尺寸及最坏编码体积；若合法现有素材超过此限，发布前调整两端一致的上限。
- 一次只允许一个上传事务，超时/断连回收仅针对有标记且未激活的临时文件。重启后不假装支持跨重启续传；重新开始新事务并清理半成品。
- 图片仍由电脑网页转换成现有 VAF1 帧，不改三屏渲染格式；完成校验、时序和帧数核对后再调用现有 activate。

- [ ] 失败用例覆盖坏 CRC、丢 ACK、重复块、乱序块、路径穿越、过大文件、ENOSPC、断线/重启、重复结束、激活失败；所有失败均不得破坏原素材。
- [ ] 实现业务层状态机，再分别接 USB 与原 HTTP，禁止两套导入规则分叉。
- [ ] 分块写文件，不在 MCU RAM 中接收整张图或整段动画；确认文件句柄、锁及错误路径释放完整。
- [ ] 仅 Codex `state/sync` 及规定的状态心跳续租任务；管理请求不更新工作状态租约，防止“后台开着就一直绿灯”。
- [ ] 执行主机故障注入、完整回归和构建；实机用小测试素材导入并确认、回切原目录，测试文件在取得授权后清除。

### Task 4 / PR 4：单一桥接提供本机后台

**Files**
- 新建 `companion_host/management_server.py`、`companion_host/management_queue.py`、`companion_host/media_transfer.py`。

**Interfaces**
- `ManagementQueue.submit(device_id: str, op: str, fields: dict, timeout: float) -> dict`；实际串口读写只在桥接所属线程执行，HTTP 线程不打开串口。
- `ManagementServer.start(queue, web_root, bind='127.0.0.1', port=17831)`、`stop()`；端口冲突明确报错并允许配置，不终止现有状态同步。
- 本地保持现有网页路径：`/api/companion`、`/api/sysinfo`、`/api/import`、`/upload/*` 及严格白名单的预览读取；二进制 HTTP 上传由电脑拆为 USB 块。
- 默认只监听 `127.0.0.1`，不向局域网开放；验证 Host、Origin/Referer，拒绝跨源写入。每次启动生成本机访问令牌，写操作必须带专用请求头；令牌不放 URL、不记日志，不等于 Codex 登录凭据。
