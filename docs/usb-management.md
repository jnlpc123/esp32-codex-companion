# USB 后台与存储管理（1.1 候选版）

板子以 USB 数据线接入 Windows，关闭其他占用串口的工具。在完整解压的新版电脑包目录运行：

```powershell
python .\companion_host\bridge.py --resume
python .\companion_host\bridge.py --status
```

打开 http://127.0.0.1:17831/。connected:true、transport:usb、management_available:true 表示已连接。浏览器页面、文件转换和 USB 传输都在本机完成，无需设备连上路由器。电脑包必须携带 web 目录的五项资源，不可仅复制 bridge.py。

设备原 Wi-Fi 后台仍可使用；状态同步继续 USB 优先、Wi-Fi 备用。USB 管理不会自动转到 Wi-Fi，拔线后显示错误；重新接入并刷新可恢复。换板后重新选择文件，旧上传不能直接发到新板。桥接重启使旧页面令牌失效，刷新页面即可。更换端口可在 companion_host/config.json 合并 management_port，保留其他已有字段。网络配对仍使用设备热点或原 Wi-Fi 后台；本机页隐藏尚未提供 USB 接口的配网表单。

## 导入素材

各屏“导入前景”支持 GIF、PNG、JPG。网页转换为现有透明动画格式并保留 GIF 时序，USB 分块写入，全部校验后才替换当前选择。失败不替换原素材；断电未完成的临时导入在下次启动回收。完成导入后无需网页常驻，下次开机自动载入。逐文件上限 256 KiB、每次一个导入；已有用户素材不会在上传空间不足时自动删除。

## 灯效与联动

在“显示与提醒 → 灯效与联动”启用背景灯效，选择闪烁、双闪、呼吸或跑马灯，调整周期后保存。默认关闭，保留既有状态颜色、任务计数与灰度暂停规则。三屏同步只控制灯效相位；跑马灯按屏幕依次点亮，但不会激活没有对应任务的状态屏。需要三个屏幕均参与时，选择“信号灯模式 → 三屏同步”，或在空闲全亮动画时使用。

“三屏动画”可独立设置：独立播放保留原时序；同步循环将不同长度素材映射到最长循环；错峰循环依次偏移三分之一周期。只有活动屏播放，未活动屏继续灰度暂停。联网和 USB 后台共用这些设备设置，保存后重启保持。高频灯效会增加共享 SPI 总线开销；30 FPS 指默认关闭灯效时适合素材的目标，并非所有 GIF 或设置的保证。

## 空间管理

总量、已用、剩余来自 SPIFFS，不是运行内存；分类显示的是逻辑文件大小，不含文件系统页和索引开销。“素材占用”可展开查看各目录。Flash 总量与文件系统可用总量不同，应用和其他分区也占空间。

“建议导入预算”另按分区约 75% 的利用范围、当前占用和 128 KiB 保留空间估算，未计入各素材的全部页开销，不保证任意文件均能写入。SPIFFS 在高占用和碎片较多时可能较早写满，不能把名义剩余容量全部用于新素材。网页与设备都会提前检查，预算不足时请先确认清除不用的素材；不会自动替你删除。参考 [Espressif SPIFFS 说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32h2/api-reference/storage/spiffs.html)。

USB 写入通过后台任务完成，电脑分次查询进度，避免垃圾回收占住串口。上传失败仍保留原选择，未完成事务可在重试或重启时回收；失败后不要把“已发送部分字节”当成导入成功。

| 按钮 | 删除范围 | 保留 |
| --- | --- | --- |
| 清除内存 | 其余已上传素材、闲置派生缓存 | 当前三屏选择的完整目录（包括灰度暂停、共享素材） |
| 全部清除 | 全部上传素材与派生缓存，包括当前展示内容 | Wi-Fi、亮度、颜色、音量、方向配置、系统及未知文件 |

两者确认后才执行；全部清除先停止播放并保存空选择。处理分批完成，页面等待最终结果；部分失败会报告，不能当成全部删除成功。删除没有界面回收站，请先保留电脑上的原图。旧 prune_cache 接口仍只清理缓存。

升级时会回收 17 项名称、大小、CRC 均匹配的原版旧网页、录音脚本和提示图片（约 145 KiB）。修改过的同名文件、方向配置、未知系统文件及上传素材不会因升级自动删除。应用压缩不会自动扩大既有 SPIFFS 分区。

## 排障

- 打不开本机页：检查 bridge.py --status，端口冲突看 management_error；不要同时运行两份桥接。
- 旧固件：能力提示要求升级。只写兼容应用至 0x10000，保留分区表、NVS、SPIFFS。
- Invalid local access token：桥接已重启，刷新页面后重试。
- USB device changed：核对当前连接板子，刷新后重新导入；不会自动重定向旧操作。
- 空间仍不够：先核对“其他素材”占用，按需确认清除内存；不会扩大 4 MiB 硬件 Flash。

本机后台无账号凭据，访问令牌仅用于本次运行的同源写校验。仅监听 127.0.0.1，不向局域网开放；原设备 HTTP 接口仍按可信局域网使用。

## 开发者验收

默认 `npm test` 需要 Python、Node 与 GCC/Clang 或 Zig；Windows 可设置 ZIG 指向 zig.exe。设置 VIBE_VALIDATION_REPORT 为绝对 JSON 路径可生成测试结果；仅干净提交的结果可用于发布打包，失败运行使旧报告失效。

硬件脚本不在默认入口中。先暂停桥接，用 `python tests/hardware/verify_usb_storage.py --port <串口> --expected-device <device_id> --temporary-upload` 检查分页、临时分块上传、完整读回、重复结束、回滚及配置保持；结束后恢复桥接。脚本不删除原素材、不激活测试导入。删除按钮、物理拔插、路由器断网、声音与长时间运行需另做实机验收。
